# 別テナントへの導入手順

このリポジトリのソースから、別の Microsoft 365 テナントに同じアプリを立てる手順。
アプリは `.msapp` を配るのではなく、**`src/` のテキストを新しいアプリに貼って作る**。

## 全体の流れ

| | 何をする | 手順 | だいたいの時間 |
|---|---|---|---|
| A | **SharePoint 側** … スクリプトを 1 回コンソールに貼る | 1〜3 | 5 分 |
| B | **Power Apps 側** … 空のアプリを作って `src/` の中身を 5 回貼る | 4〜6 | 20 分 |
| C | **動作確認と共有** | 7〜8 | 10 分 |
| D | **本番データを入れる** … 管理タブから CSV を貼る | 下記 | 10 分 |
| E | **2 回目以降を自動化する**（任意） | 9 | 20 分 |

**A が終わるまで B に進まない**（B の途中でリストを繋ぐため）。
**初回は必ず A→B を通す。** ソリューションごと別テナントへ運ぶのは向かない（→ 6-6）。

## D. 本番データの入れ方（手順 7 のあと）

**手作業でマスタを打ち込む必要はない。** アプリの「管理」タブから CSV を貼り付ける。

1. 手順 1 を `DO.seed = false` で流していれば、マスタは空のまま
2. アプリを開き、**管理タブ**（管理者だけに出る）へ
3. **組織の親子 → 組織マスタ → ユーザマスタ** の順に貼って「取り込む」

見出しと形式は [features.md](features.md) の「管理タブ」を参照。Excel から直接貼れる。

**取り込んだデータだけでログインできる。** アプリはログイン者を
`AdObjectId` → **メールアドレス** の順で引くので、CSV に自分の行が入っていれば足りる。

> Entra ID のメールアドレスとマスタの `Mail` が**一致している必要がある**。
> 別名（エイリアス）でログインしている場合は引けないので、
> そのときだけ手順 2 の方法で `AdObjectId` を入れる。

やり直したいときは、同じ管理タブの **登録データの一括クリア**でマスタと申請履歴を消せる。
設定（管理者グループ）は残る。

## 1. SharePoint を用意する

[setup/setup.js](../setup/setup.js) を 1 回貼って実行するだけ。
**リスト 8 本・列・索引・一意制約・ダミーのマスタ・自分の紐付け・管理者グループ**が揃う。

先頭の 2 か所を直す。

```js
const SITE_URL = "https://YOUR-TENANT.sharepoint.com/sites/YOUR-SITE";

const DO = {
  lists:    true,  // リスト 8 本・列・索引・一意制約
  seed:     true,  // ダミーのマスタ（本番では false）
  bindMe:   true,  // 今ログインしている自分を BIND_GID の利用者に紐づける
  adminMe:  true,  // このサイトの Microsoft 365 グループを管理者グループにする
  backfill: false, // 承認機能より前に作ったサイトの後始末
};
```

| 用途 | `DO` |
|---|---|
| **検証環境**（空サイトに一発で動くものを作る） | 既定のまま |
| **本番**（実データを自分で入れる） | `seed` / `bindMe` / `adminMe` を `false`。手順 2・3 を手でやる |
| **既存サイトの更新**（列だけ足す） | `lists` だけ `true` |

### 実行のしかた

1. 対象の SharePoint サイトをブラウザで開く（**サイト所有者権限のアカウント**で）
2. `F12`（Mac は `Cmd+Option+I`）で開発者ツールを開き、**Console** タブを選ぶ
3. **初回はここで貼り付けが拒否される。** Chrome / Edge は
   `Warning: Don't paste code into the DevTools Console...` と出すので、
   コンソールに **`allow pasting` と手で打って Enter**。以後は貼れる
4. `setup.js` の全文を貼って Enter
5. `[PRM] …` のログが流れ、最後に `[PRM] 完了。` が出れば成功。
   赤い `[PRM] 失敗:` が出たら**そこで止めて内容を確認する**（途中まで作られた状態でも、
   直してもう一度流せば続きから埋まる）

**何度実行しても安全**で、既にあるリスト・列・選択肢・行は飛ばす。

正常なログはこうなる（空サイトの場合）。

```
[PRM] PRM_Org1 作成
[PRM] PRM_Org1.NameJa を追加
   …
[PRM] リスト・列・索引・一意制約を確認
[PRM] PRM_Org1 投入 2 件 / 既存 0 件
   …
[PRM] 1234567 を自分に紐づけた（アプリはこの人として動く）
[PRM] AdminGroupId にこのサイトのグループを設定（このチームのメンバーが管理者）
[PRM] 完了。次はアプリを作る → docs/deploy.md 手順 4 から
```

## 2. ログイン者の紐付け（`bindMe` を `false` にしたとき）

アプリは **ログイン中のユーザを `PRM_Users` から引く**。オブジェクト ID で引き、
空振りしたら**メールアドレス**で引く。どちらも当たらなければフォールバックに落ちる。

```
Set(gblMe, LookUp(PRM_Users, AdObjectId = gblMyAdId));
If(IsBlank(gblMe.Title) && !IsBlank(gblMyMail), Set(gblMe, LookUp(PRM_Users, Mail = gblMyMail)));
Set(gblMeGid, If(IsBlank(gblMe.Title), "1234567", gblMe.Title));
```

**CSV で取り込んだ利用者はメールで引ける**ので、この手順は
エイリアスでログインする場合など、メールが一致しないときだけ必要。

引けないと `gblMeGid` が `"1234567"` に落ちる。新しいテナントにその ID の人は居ないので、
**所属が 1 件も取れず、組織マスタもユーザマスタも空で開く**。

`bindMe: true` ならスクリプトが自動でやる（SharePoint のユーザープロファイル
`msOnline-ObjectId` を読んで `PRM_Users` に書く）。手でやる場合は次を入れる。

| リスト | 入れる行 |
|---|---|
| `PRM_Org1` | 組織区分1 を 1 件以上（`Title` = コード、`NameJa`、`SortOrder`、`IsActive` = はい） |
| `PRM_Org2` | その配下の組織区分2（`Title` = コード、`Org1Code`、`NameJa`、`SortOrder`、`ApExt`/`ApWlan`/`ApCloud`、`IsActive` = はい） |
| `PRM_Users` | 自分（`Title` = グローバルID、`FullName`、**`AdObjectId`**、`IsActive` = はい） |
| `PRM_UserOrg1` | `Title` = `<グローバルID>#<組織区分1コード>`、`GlobalId`、`Org1Code`、`IsActive` = はい |

オブジェクト ID は Entra ID 管理センターのユーザー詳細「オブジェクト ID」、または
対象サイトのコンソールで次を実行しても取れる。

```js
(await (await fetch("/_api/SP.UserProfiles.PeopleManager/GetMyProperties?$select=UserProfileProperties",
  { headers: { Accept: "application/json;odata=nometadata" } })).json())
  .UserProfileProperties.find(p => p.Key === "msOnline-ObjectId").Value
```

### 本番に出す前にフォールバックを外す

`"1234567"` のままだと、マスタ未登録の人が**全員そのグローバルIDとして申請できてしまう**。
本番テナントでは `App.OnStart` のこの箇所を空文字にして、
未登録なら申請させない作りに変えること（現状は未実装。ヘッダには「未登録」と出るだけ）。

## 3. 管理者グループ（`adminMe` を `false` にしたとき）

`PRM_Config` の `AdminGroupId` 行の `Value` に、管理者にする Teams（Microsoft 365 グループ）の
ID を入れる。そのチームの SharePoint サイトで `/_api/site?$select=GroupId` を開けば分かる。

`adminMe: true` なら、**スクリプトを流したサイト自身のグループ**が設定される
（そのチームのメンバー全員が管理者になる）。別のグループにしたいときは手で入れ直す。

空のままだと申請履歴・申請詳細に **確認中／完了／差し戻し が出ない**
（＝誰も申請を完了にできず、マスタに反映されない）。申請と取り下げはできる。

## 4. アプリの器を作る

1. [make.powerapps.com](https://make.powerapps.com) を開く
2. **右上の「環境」**が目的の環境になっているか確かめる（違う環境に作ると後から移せない）
3. 左メニュー **「作成」→「空のアプリ」→「空のキャンバスアプリ」**
4. アプリ名を入れて作成（形式はどちらでもよい。次でレスポンシブにする）

作られたら、先に**アプリ全体の設定**を 2 つ変える。上部の **「設定」**（歯車）から:

| 場所 | 変えるもの | なぜ |
|---|---|---|
| 設定 → 更新 → 新規 | **「モダン コントロールとモダン テーマ」を ON** | このアプリは `ModernText` / `ModernTextInput` / `ModernDropdown` で作られている。OFF のまま貼るとコントロールが解決しない |
| 設定 → 表示 | **アプリ レイアウトを「レスポンシブ」** | 画面は `Parent.Width` / `Parent.Height` 基準。固定サイズだと右端が切れる |

続けてデータソースを繋ぐ。左のリボンの **「データの追加」**から:

- **SharePoint** … 接続を選び、手順 1 のサイト URL を入れて `PRM_*` **8 本すべて**にチェック
  （`PRM_Config` を忘れやすい）
- **Office 365 ユーザー**
- **Office 365 グループ**

> 8 本のうち 1 本でも欠けると、貼り付けたときに
> `名前が無効です: 'PRM_Config' は認識されません` のような数式エラーが大量に出る。

## 5. コネクタ名を環境の言語に合わせる

**コネクタの参照名は環境の表示言語になる。** 日本語環境で採取したソースは
`Office365ユーザー` / `Office365グループ` と書いてある。英語環境なら
`Office365Users` / `Office365Groups`。このまま貼ると名前エラーになる。

確かめ方: 適当なラベルを 1 つ置き、**数式バーに `Office365` と打つ**と候補が出る。
違っていたら、貼る前にソースを置換する。

```bash
sed -i '' 's/Office365ユーザー/Office365Users/g; s/Office365グループ/Office365Groups/g' src/App.OnStart.txt
```

使っているのは `App.OnStart` の 2 か所だけ（`MyProfileV2` と `ListGroupMembers`）。

## 6. ソースを流し込む

**順番を守る。** 画面は `App.Formulas` の名前付き数式を参照しているので、先に数式を入れる。

| # | 貼り先 | ソース |
|---|---|---|
| 1 | `App.Formulas` | [src/App.Formulas.txt](../src/App.Formulas.txt) |
| 2 | `App.OnStart` | [src/App.OnStart.txt](../src/App.OnStart.txt) |
| 3 | 画面 | [src/ScrHome.pa.yaml](../src/ScrHome.pa.yaml) |
| 4 | 画面 | [src/ScrUser.pa.yaml](../src/ScrUser.pa.yaml) |
| 5 | 画面 | [src/ScrReq.pa.yaml](../src/ScrReq.pa.yaml) |

### 6-1. クリップボードに入れる

`pbcopy` は既定で UTF-8 にならないので、**文字コードを必ず指定する**。

```bash
LC_CTYPE=UTF-8 pbcopy < src/App.Formulas.txt
```

入ったか確かめる（バイト数がファイルと合えば OK）。

```bash
LC_CTYPE=UTF-8 pbpaste | wc -c
```

> Windows なら `Get-Content -Raw -Encoding UTF8 src\App.Formulas.txt | Set-Clipboard`。

### 6-2. `App.Formulas` と `App.OnStart`（1〜2 番）

1. 左の**ツリービュー**でいちばん上の **`App`** をクリック
2. **数式バーの左にあるプロパティのドロップダウン**（既定で `Fill` などが出ている箱）を開く
3. 一覧から **`Formulas`** を選ぶ（`App` を選んでいるときだけ候補に出る）
4. 数式バーの中をクリック → `Cmd+A` → `Delete` → `Cmd+V`
5. 同じ手順で **`OnStart`** を選び、`App.OnStart.txt` を貼る

**貼る前に必ずプロパティを選ぶ。** 選び忘れて `Text` のまま貼ると、
`非動作プロパティに動作関数があります` と言われて壊れる。
数式バーが縦に伸びていて操作しにくいときは、**右端の `⌄`** で開閉できる。

### 6-3. 画面（3〜5 番）

画面は数式バーではなく、**ツリービューのメニューから貼る**。

1. `src/ScrHome.pa.yaml` をクリップボードに入れる（6-1）
2. ツリービューで**既にある画面**（新規作成時の `Screen1` でよい）に**マウスを載せると
   右端に出る `…`** をクリック
3. メニューの **「貼り付け」**
4. `ScrUser` → `ScrReq` も同じ手順で入れる

引っかかりやすい点:

- **メニュー項目の位置は固定ではない。** 画面が先頭だと「上へ移動」が消えて
  1 行ぶん上にずれる。**押す前に文字を読む**（「削除」と「貼り付け」を間違えやすい）
- **同名の画面が既にあると、貼り付けたほうに黙って `_1` が付く。**
  貼り直すときは**先に古い画面を「削除」してから貼る**
- コントロール名はアプリ全体で一意。別画面に同名があっても `_1` が付く
- 数式バーが開いたままだと `…` メニューが反応しないことがある。
  一度 `Esc` を押すか、数式バーを閉じてからクリックする

### 6-4. 仕上げ

1. ツリービューの `App` の `…` →「**StartScreen に移動する**」で開き、
   `App.StartScreen` を **`ScrHome`** にする
2. **空の `Screen1` を削除**（3 画面を貼ったら不要）
3. `Cmd+S`（Windows は `Ctrl+S`）で**保存**
4. 上部の**聴診器アイコン「アプリのチェック」→「数式」**を開き、**エラーを 0 にする**
   - **エラーのあるプロパティは黙って実行されない。** `OnSelect` がエラーだと
     ボタンが無反応になるが、警告は何も出ない
   - 名前エラーが大量に出るなら、データソースの繋ぎ忘れ（手順 4）か
     コネクタ名の言語違い（手順 5）を疑う
5. ツリービューの `App` の `…` →「**OnStart を実行します**」を押す
   - **貼り替えても自動では走らない。** プレビュー（▷）でも再実行されない

### 6-5. 初回だけ出る「アクセス許可」

プレビューまたは初回実行時に **「もう少しで終了します…」**というダイアログが出て、
`Office 365 ユーザー` / `Office 365 グループ` へのアクセス許可を求められる。
**「許可」**を押す。押さないとログイン者の特定と管理者判定ができない。

## 6-6. ソリューションごと運ぶのは別テナントには向かない

「移行元でソリューションに入れて export → 移行先で import」で画面の貼り付けを省けそうに見えるが、
**別テナントでは勧めない。**

`.msapp` に**移行元のサイト URL と各リストの GUID が焼き込まれている**ため。実測すると:

| 入っている場所 | サイト URL | リストの GUID |
|---|---|---|
| `References/DataSources.json` | 32 か所 | 8 リスト分 |
| `Properties.json` | 1 か所 | 8 リスト分 |

このまま取り込むと**移行先のアプリが移行元のサイトを見に行く**。取り込んだあと Studio で
データソースを 8 本とも外して入れ直すことになり、手順 4 で 10 本つなぐのと手間が変わらない。
しかも張り替えで数式エラーが残らないかは**未検証**。

同じテナント内（同じサイトを見る）なら話は別で、そちらは実績がある → [docs/cli.md](cli.md)。

**別テナントには手順 1〜6 を使う。** そのうえで、そのテナントでの 2 回目以降の更新を
コマンド 1 発にしたい場合は手順 9 へ。

## 7. 通しで確認する

- [ ] ヘッダ右上に**自分の氏名とグローバルID**が出る（「未登録」なら手順 2 に戻る）
- [ ] 組織マスタに組織区分1 の要否と組織区分2 の一覧が出る
- [ ] ユーザマスタのマトリックスに人が並ぶ
- [ ] 管理者アカウントなら、申請履歴の行に 確認中／完了／差し戻し が出る

- [ ] その申請を開いて `完了にする` → **SharePoint のリストが書き換わる**
- [ ] 検証で入れた変更を元に戻す

## 7-1. 画面は出るのに何も表示されないとき

いちばん多い症状。**枠だけ描かれて、組織区分2 の一覧もユーザのマトリックスも空**になる。
上から順に潰す。

### ① `App.OnStart` を実行したか（最有力）

ツリービューの `App` を右クリック →「**OnStart を実行します**」。

**貼り替えても、プレビュー（▷）でも自動では走らない。** OnStart が走っていないと
コレクションが全部空なので、画面は出るがデータが 1 行も無い状態になる。

### ② 変数の中身を見る

左のリボンの **`{x}`（変数）** を開き、「コレクション」で行数を見る。

| 見えるもの | 意味 | 次に見るところ |
|---|---|---|
| `colOrg1` が 0 行 | **データを読めていない** | ①、または「データの追加」で `PRM_*` 8 本が繋がっているか、③のコネクタ許可 |
| `colOrg1` に行があるが `colMyOrg1` が 0 行 | **ログイン者に所属が無い** | ④ |
| どちらも行がある | 表示側の問題。`gblOrg1` が入っているか見る | — |

### ③ コネクタのアクセス許可を押したか

初回に出る「もう少しで終了します…」で「**許可**」を押していないと
`Office365ユーザー.MyProfileV2()` が失敗し、ログイン者を特定できない。
「許可しない」を押してしまった場合は、アプリを開き直すともう一度出る。

### ④ ログイン者とグローバルIDの対応付け

`gblMeGid`（変数パネルで見える）が誰になっているかを確認する。

- **`1234567` になっている** … 対応付けに失敗してフォールバックしている。
  ダミーデータが入っていればこれでも表示されるはずなので、
  表示されないなら `PRM_UserOrg1` に `1234567#B01` の行があるか確認する
- **空になっている** … `PRM_Users` が読めていない

**グローバルID は Entra ID に存在しない独自の ID。** Entra ID 側から自動で引くことはできないので、
`PRM_Users.AdObjectId` に Entra ID のオブジェクト ID を入れた対応表だけが手がかりになる。
`setup.js` の `bindMe` はこれを 1 人分だけ自動で入れる。**残りの利用者は運用で埋める**
（AD 同期は未実装）。

### 確認用: アプリが見ているオブジェクト ID

一時的にラベルを 1 つ置いて `Text` に次を入れると、アプリ側が見ている値が出る。
`setup.js` が書いた `PRM_Users.AdObjectId` と一致しているか比べる。

```
=Office365ユーザー.MyProfileV2().id & " / " & gblMeGid & " / " & gblOrg1
```

> `setup.js` は SharePoint のユーザープロファイル `msOnline-ObjectId` を使っている。
> これが `Office365ユーザー.MyProfileV2().id` と一致することは**実機で確認済み**
> （`bindMe` で書き込んだあと、ヘッダに氏名とグローバルIDが出ることで確かめた）。

## 9. そのテナントで `deploy.ps1` を使えるようにする（初回だけ）

ここまでで導入は終わり。**2 回目以降の更新を「貼り付け 5 回」から「コマンド 1 発」に
変えたい場合だけ**、続けて次をやる。同一テナント内なので、6-6 の問題は起きない。

### 9-1. `pac` を入れて認証する

**コマンドだけで入る。**

```powershell
winget install Microsoft.DotNet.SDK.10
```

**ここで新しいターミナルを開く**（PATH を読み直すため）。続けて:

```powershell
dotnet tool install --global Microsoft.PowerApps.CLI.Tool
```

**バージョンは 10 でないと駄目。** `pac` は NuGet に出ている**全バージョンが
`net10.0` 専用**で、SDK 9 以下だとインストール自体が次で失敗する。

```
設定ファイル 'DotnetToolSettings.xml' がパッケージで見つかりませんでした
ツール 'microsoft.powerapps.cli.tool' をインストールできませんでした
```

`--version` で古い pac を指定しても回避できない（2.2.1 まで遡っても `net10.0` のみ）。

.NET SDK を先に入れるのは、**`dotnet tool install` に SDK が要る**ため。
ランタイムだけ入っている PC では `No .NET SDKs were found` で失敗する。

> **`winget install Microsoft.PowerAppsCLI` は使わない。**
> 中身が `powerapps-cli-1.0.msi` で古く、このリポジトリが使う
> `--layout SourceCode` が無い（winget にはこの 1.0 しか無い）。
> `deploy.ps1` は古い `pac` を検出して最初に止まる。

入れたら認証する。

```powershell
pac auth create --name permhub
```

ブラウザでサインイン画面が出る。**Entra ID のアプリ登録・サービスプリンシパルは不要**、
**Premium も不要**。無人実行（GitHub Actions 等）にするときだけアプリ登録が要る。

> **`--name` は自分で好きに付ける手元のラベル。** テナント名やアカウント名とは関係なく、
> どこにも送信されない。30 文字まで。**この PC に複数テナントの接続を保存して切り替える
> ためだけのもの**なので、1 テナントしか使わないなら `permhub` でよい。
>
> 複数のテナントを行き来するなら、区別できる名前にしておく。
>
> ```powershell
> pac auth create --name permhub-honban    # 本番テナント
> pac auth create --name permhub-kensho    # 検証テナント
>
> pac auth list        # 保存済みの一覧（* が今使っているもの）
> pac auth select --index 2   # 切り替え
> pac auth who         # 今どのテナントに繋がっているか
> ```
>
> **`deploy.ps1` は「今アクティブなプロファイル」のテナントに対して実行される。**
> 流す前に `pac auth who` で行き先を確かめる。

### 9-2. ソリューションを作る

ポータルの **ソリューション →「新しいソリューション」**。表示名と名前を入れる。
**名前**（一意名）が `-SolutionName` に渡す値になる。

**公開元はどれでもよい。** 一覧に `CDS Default Publisher` が複数あってもどれを選んでも動く。
公開元が決めるのは**接頭辞**だけで、ソリューションの中でファイル名が

```
CanvasApps/cr875_permhubsolutiontest_09c62_DocumentUri.msapp
           ~~~~~ ← 公開元の接頭辞
```

のようになる。`deploy.ps1` は `*.msapp` で拾うので接頭辞に依存しない。

> 組織で使う公開元が決まっているならそれに従う。決まっていないなら既定のものでよい。
> あとで**マネージド ソリューションとして配布する**なら公開元が意味を持つが、
> ここでは同じテナント内でアプリを更新するだけなので関係ない。

### 9-3. アプリをソリューションに追加する

**「既存を追加」→「アプリ」→「キャンバス アプリ」→「Dataverse の外部」**タブ
→ アプリを選んで「追加」。

ここで 2 つ引っかかる。**どちらもライセンスの問題ではない。**

| 症状 | 原因と対処 |
|---|---|
| 作ったばかりのアプリが一覧に出ない（検索しても出ない） | インデックスの反映待ち。**20 分ほどで出る** |
| `'<アプリ名>' is locked by user ...` で追加できない | **そのアプリを Studio で開いている。** タブを閉じる（別ページへ移動する）と**すぐ**解放される。メッセージの「15 分待て」はブラウザが落ちて解放を伝えられなかったときの上限 |

> ソリューション画面に `この環境への現在の特典が不十分であるため、1 つ以上のコマンドを
> 使用できません` が常時出ることがあるが、**キャンバスアプリの追加はこれに阻まれない**。

### 9-4. 使う

```powershell
.\setup\deploy.ps1 -SolutionName <ソリューションの一意名>
```

`src/*.pa.yaml` を直してこれを叩けば、アプリが更新されて公開まで済む。
詳細と手で叩く版は [docs/cli.md](cli.md)。

### 9-5. `deploy.ps1` でつまずくところ

| 出るもの | 意味 |
|---|---|
| `pac が見つからない` | .NET SDK **10** を入れてから `dotnet tool install --global Microsoft.PowerApps.CLI.Tool`。SDK 9 以下だと `DotnetToolSettings.xml がパッケージで見つかりませんでした` になる |
| `The given solution unique name (xxx) is not valid` | 一意名の取り違えか、そのテナントで 9-2 / 9-3 をまだやっていない。スクリプトがその場で一覧を出す |
| 日本語が化けて `式またはステートメントのトークン ... を使用できません` が大量に出る | `deploy.ps1` の **UTF-8 BOM が外れた**。Windows PowerShell 5.1 は BOM 無しの `.ps1` を CP932 として読む。リポジトリから取り直す |
| `CanvasApp import: FAILURE: The solution specified an expected assets file but that file was missing or invalid` | **古い `deploy.ps1`**。zip を解凍して詰め直していた版は、Windows だと zip 内のパス区切りが円記号になり取り込みが本体を見つけられない。取り直す（→ [cli.md](cli.md)） |
| `gblIsAdmin` など名前エラーが大量に出る | データソース名が合っていない。`App.OnStart` 全体がエラーになり変数がセットされない。`deploy.ps1` が `! src が使っているのにアプリに無い名前` として出す |
| 画面は出るのにデータが空 | `App.OnStart` が動いていない。→ 7-1。`OnStart` にエラーがあると黙って実行されない |
| `! App.OnStart がアプリ側と違う` | アプリの `App.OnStart` がリポジトリと違う。反映するなら `-WithApp`（→ [cli.md](cli.md)） |
| `error PA2110 : An entity with name 'xxx' already exists` | アプリに `src` に無い画面が残っていて、コントロール名がぶつかっている。要らない画面なら `-PruneScreens` を付けて消す（→ [cli.md](cli.md)） |
| `Cannot start another [Import] because there is a previous [Import] running` | 直前の操作が裏で走っているだけ。スクリプトが 40 秒おきに 6 回まで自動で待ち直す |

## 9-6. まっさらな環境での立ち上げ（検証済みの手順）

**この順番でないと動かない。** データソースはリストの GUID とサイト URL に
紐づいているので、**YAML では作れない**。アプリ側で自分で追加するしかなく、
それが済むまで `deploy.ps1` は画面を入れても壊れたアプリになるだけ。

順に、これだけ。

1. **SharePoint のリストを作る** — `setup/setup.js`（手順 1）。8 本できる
2. **空のキャンバスアプリを作る** — 「空のアプリ」→ タブレット。
   **SharePoint リストからは作らない**（余計な画面とデータソースが付いてくる）
3. **データソースを 10 個追加する** — 左の「データ」→「データの追加」

   | 種別 | 名前 |
   |---|---|
   | SharePoint リスト | `PRM_Config` `PRM_Grants` `PRM_Org1` `PRM_Org2` `PRM_RequestItems` `PRM_Requests` `PRM_UserOrg1` `PRM_Users` |
   | コネクタ | `Office365ユーザー` `Office365グループ`（英語環境なら `Office365Users` / `Office365Groups`） |

4. **保存して、公開して、タブを閉じる** — **保存だけでは足りない。**
   `pac solution export` が取ってくるのは**公開済みのバージョン**なので、
   公開しないとデータソースを足したことが反映されず、`deploy.ps1` が
   「アプリに無い名前」として 10 個とも並べて止まる。
   右上「公開」→「このバージョンを公開する」。開いたままだとソリューションにも追加できない
5. **ソリューションを作り、このアプリを追加する** — 9-2 / 9-3
6. **流し込む**

   ```powershell
   .\setup\deploy.ps1 -SolutionName <一意名> -WithApp -PruneScreens
   ```

   `-WithApp` で `App.Formulas` と `App.OnStart` が入る。`-PruneScreens` で
   `Screen1` が消える。`StartScreen` は自動で `ScrHome` に付け替わる

7. **アプリを ▷ で開く** — `App.OnStart` は起動時に走る。Studio は要らない

> **取り込んだだけでは利用者に配られない。** キャンバスアプリは「保存された版」と
> 「公開された版」が別で、`deploy.ps1` は取り込みのあと公開まで行う。
> Windows PowerShell 5.1 が無い環境では公開を飛ばすので、Studio で
> 「公開」→「このバージョンを公開する」を押す。→ [cli.md](cli.md)

2 回目以降は `-WithApp` も `-PruneScreens` も要らない。

```powershell
.\setup\deploy.ps1 -SolutionName <一意名>
```

> **手順 3 を飛ばすと `deploy.ps1` は止まる。** 足りないデータソース名を並べて
> 終了コード 1 で抜ける。壊れたアプリを作らないため。
>
> この 1〜7 は dev 環境で、アプリを「空アプリ＋データソースだけ」の状態に戻してから
> 通しで実行し、`src` と一致する 3 画面・`App.Formulas` 80 行・`App.OnStart`・
> `StartScreen = ScrHome`・データソース 12 件が揃うことを確認してある。

## 10. テナントに合わせて直す前提値

そのままでは合わない可能性が高い箇所。**手順 6 の前にソースを直す**方が、
あとから Studio で追うより早い。

| 前提 | 今の値 | 直す場所 |
|---|---|---|
| 権限 6 種のコードと名称 | `SECMGR` 事業場ITセキュリティ責任者 / `CONFORM` 適合化担当 / `EXTCONN` 外部接続申請担当 / `WLAN` 無線LAN申請担当 / `CLOUD` クラウド申請担当 / `INFOSEC` 情報セキュリティ担当 | `App.Formulas` の `fRoles`、`ScrHome` の権限種別タブ、`ScrUser` の役割行。**種類を増減するならコントロールの追加・削除が要る**（1 種別 = 1 コントロール） |
| グローバルID の書式 | 数字 7 桁 または 英字 1 桁 + 数字 6 桁 | `ScrUser` の `IsMatch(gblNewGid, "^([0-9]{7}\|[A-Z][0-9]{6})$")` |
| 組織区分2 のコード採番 | `"A"` + 組織区分1 コードの下 2 桁 + 連番 2 桁（`B01` → `A0101`） | `App.Formulas` の `fO2NextCode` |
| 多段階承認の 3 種 | 外部接続 / 無線LAN / クラウド | 列そのもの（`PRM_Org2.ApExt/ApWlan/ApCloud`）。増減はスキーマ変更 |
| 未登録者のフォールバック | `"1234567"` | `App.OnStart`（手順 2） |
| 申請履歴の取得範囲 | 直近 365 日 | `App.OnStart` の `DateAdd(Now(), -365, TimeUnit.Days)` |

## 11. 引っかかりやすいところ

- **SharePoint に列や選択肢を足したら、Power Apps 側でデータソースを「最新の情報に更新」する。**
  しないと `名前が無効です: 'ItemStatus' は認識されません` になる
- **`App.OnStart` は貼り替えても自動では走らない。** プレビュー（▷）でも再実行されない
- **コントロール名はアプリ全体で一意。** 既存の画面と名前が衝突すると、貼り付け時に黙って `_1` が付く。
  貼る前に古い画面を消す
- **`App.Formulas` は定義ごとに `;` で終える。** 末尾に追記して直前の `;` を落とすと、
  その定義が丸ごと消えて「名前が無効です」が全画面に出る
- **`PRM_RequestItems` は消さないと 5,000 行を超える。** 保持期間の運用を決めておく
- 詳しい制約は [powerapps-controls.md](powerapps-controls.md) と [README](../README.md) の「実装で分かった制約」
